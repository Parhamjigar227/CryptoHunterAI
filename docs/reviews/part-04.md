# بازبینی قسمت ۴ — رابط کاربری و گزارش

## فایل‌ها
| فایل | هدف |
|---|---|
| `public/index.html` (تغییر) | افزودن صفحهٔ «تحقیق هوشمند» (فرم، وضعیت مراحل، خطا، گزارش، تاریخچه) به‌عنوان صفحهٔ پیش‌فرض؛ صفحه‌های ردیاب قبلی دست‌نخورده‌اند |
| `public/js/markdown.js` | رندر Markdown امن (همه‌چیز escape؛ فقط لینک http/https) |
| `public/js/research.js` | ارسال فرم به `POST /api/research`، خواندن استریم NDJSON، نمایش مراحل و خطاها، ذخیرهٔ Markdown/HTML، کپی، تاریخچهٔ محلی (localStorage، حداکثر ۲۰)، نشان وضعیت از `/api/health` |
| `public/css/style.css` (تغییر) | استایل گزارش |
| `tests/frontend.test.js` | آزمون واحد رندر Markdown (از جمله payloadهای XSS)، پارسر NDJSON و HTML خروجی |
| `tests/e2e/server.mjs`, `tests/e2e/ui.e2e.mjs` | آزمون مرورگر (Playwright + Chromium) علیه کد واقعی Worker |

## آزمون‌های اجراشده
- `npm test`: **۶۴ آزمون، همه پاس**.
- `npm run test:e2e` (Chromium واقعی): **۷ آزمون، همه پاس**: مسیر کامل فرم→استریم→گزارش، خنثی‌شدن HTML تزریقی مدل، دانلود `.md` و `.html`، تاریخچه (ماندگاری بعد از reload، نمایش، حذف)، خطای اعتبارسنجی سرور (SSRF)، توکن دسترسی (۴۰۱ بدون توکن/موفق با توکن)، سهمیهٔ تمام‌شدهٔ AI، نبود شواهد، سرریز افقی موبایل (۳۹۰px)، و سالم‌ماندن صفحه‌های ردیاب قبلی.
- اسکرین‌شات دسکتاپ و موبایل به‌صورت بصری بررسی شد (راست‌چین، جدول، لینک‌ها).

## مهم: این آزمون‌ها چه چیزی را **ثابت نمی‌کنند**
در آزمون مرورگر، سایت/CoinGecko/GitHub و binding هوش مصنوعی **شبیه‌سازی‌شده‌اند** و Worker در Node اجرا می‌شود، نه workerd. پس ارتباط رابط↔API و منطق ثابت شده؛ کارکرد با اینترنت واقعی، Workers AI واقعی و runtime کلودفلر ثابت نشده است.

## محدودیت‌ها
- تاریخچه فقط در همان مرورگر است (بدون سرور/دیتابیس، عمداً).
- توکن دسترسی در `sessionStorage` همان تب نگه داشته می‌شود.
- رندر Markdown عمداً ساده است (بدون تصویر، بدون HTML خام).
- فونت Tahoma/Arial سیستم؛ فونت فارسی اختصاصی بارگذاری نمی‌شود.
