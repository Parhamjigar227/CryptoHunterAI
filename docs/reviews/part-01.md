# بازبینی قسمت ۱ — زیرساخت و اعتبارسنجی

## فایل‌ها
| فایل | هدف |
|---|---|
| `wrangler.jsonc` | تعریف Worker، سرو `public/` به‌عنوان asset، `run_worker_first` برای `/api/*`، binding هوش مصنوعی، مدل پیش‌فرض |
| `package.json` | اسکریپت‌های `test`/`dev`/`deploy`؛ تنها وابستگی: `wrangler` (dev) |
| `src/validate.js` | اعتبارسنجی ورودی و URL (تابع‌های خالص، بدون شبکه) |
| `src/worker.js` | مسیریابی، `GET /api/health`، `POST /api/research` (اعتبارسنجی، توکن اختیاری، محدودیت اندازهٔ بدنه)، خطای ساخت‌یافتهٔ JSON |
| `tests/validate.test.js`, `tests/worker.test.js` | آزمون‌های واحد |
| `public/**` | رابط قبلی (بدون تغییر محتوا؛ فقط جابه‌جایی با `git mv`) |
| `.gitignore` | `node_modules`, `.dev.vars`, `.env` |
| `STATUS.md` | وضعیت و ادامهٔ کار |

## اجرا
`npm test` → ۱۷ آزمون، همه پاس (اجرا شده در همین محیط، Node v22.22.0).

## آنچه آزمایش نشده
- `wrangler dev` / استقرار اجرا نشده (حساب Cloudflare در محیط توسعه نیست).
- مسیر static assets با `run_worker_first` فقط در آزمون با `ASSETS` شبیه‌سازی‌شده بررسی شد، نه روی runtime واقعی.

## محدودیت‌های شناخته‌شده
1. **SSRF:** فقط نام میزبان بررسی می‌شود. دامنهٔ عمومی‌ای که DNS آن به IP داخلی اشاره کند در Workers قابل پیش‌گیری سطح-اپلیکیشن نیست؛ Workers از شبکهٔ داخلی کلودفلر نیز به‌طور پیش‌فرض به شبکهٔ خصوصی دسترسی ندارد. ریدایرکت‌ها در قسمت ۲ دستی و با اعتبارسنجی مجدد دنبال می‌شوند.
2. **Rate limit:** هنوز وجود ندارد. تا آن زمان، `ACCESS_TOKEN` تنها محافظ سهمیه است.
3. دامنه‌های یونیکد باید punycode باشند (رد می‌شوند در غیر این صورت).

## وابستگی‌ها
`wrangler` (devDependency). نصب نشده؛ فقط در `npm install` گرفته می‌شود.
